## 四、重要前提（读改动前必须知道）

1. **本窗口提交存在本地/远端的 SHA 重复对**。因推送走 Git Data API（`scripts/push-api.py`），本地提交与远端接收的提交内容相同但 SHA 不同：
   - `3bb87ae`（本地）= `0c1ef6f`（远端 API 接收）—— GitHub 文档/署名 + cp1252 构建修复
   - `0054bfa`（本地）= `6379bb98`（远端 API 接收）—— CI 冒烟竞态修复
   - v1.1.0 直接以 `1bc1355` 推上远端；push-api 修复 `e7d97bb`、NSIS 修复 `f9286c2` 远端同 SHA。
   - 因此本目录的「改动清单」按**内容**而非 SHA 去重，凡出现重复对都标注了对应关系。
2. **本机有 TLS 拦截代理**：系统 `curl` 走系统证书链可连通 `api.github.com`，Python 自带 OpenSSL 证书链会 `SSL EOF`。`scripts/push-api.py` 已改为全程走 `curl` 子进程 + `--retry 5` + 临时文件传体。详见 `02-本窗口改动清单.md` 第六节。
3. **本仓库开启 `core.autocrlf`**：本地提交存 CRLF、API 推送存 LF，会导致树 SHA 漂移与伪分叉。对齐远端用 `git -c http.sslBackend=schannel fetch origin main && git reset --hard origin/main`。
4. **`desktop/build/icon.ico` 已入库**：此前 `.gitignore` 的 `build/`（无前导斜杠，匹配任意层级）误伤了它，已在 v1.1.0 阶段修复并入库，**勿删**。
