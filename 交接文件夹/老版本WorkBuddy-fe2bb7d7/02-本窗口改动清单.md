### 3.5 推送链路与 CI 修复（#19–#21）

**#19 `e7d97bb` push-api.py 改用 curl**（1 文件，`scripts/push-api.py` 36 行改）：
- 背景：本机 TLS 拦截代理下，Python `urllib` 访问 `api.github.com` 报 `SSL EOF`；系统 `curl` 走系统证书链可通。
- 改动：HTTP 调用统一改为 `curl` 子进程；加 `--retry 5` 抗间歇性连接重置；请求体写临时文件 `-d @file` 传，避开大文件 base64 后的命令行长度上限（`Argument list too long`）。

**#20 `f9286c2` 修复 CI Windows NSIS 打包失败**（5 文件）：
- 根因：`.gitignore` 的 `build/`（无前导斜杠，匹配任意层级）把 `desktop/build/icon.ico`（electron-builder 必需）整目录忽略，本地有、CI checkout 无 → `cannot find specified resource "build/icon.ico"`（runs #14–#19 持续红）。
- 改动：`.gitignore` 增加 `!desktop/build/`、`!desktop/build/**`；`desktop/build/icon.ico`（50,194 字节）入库；`scripts/build-exe.py` electron-builder 加 `--publish never`（防 CI 下隐式发布缺 GH_TOKEN 二次失败）；`.workbuddy/memory/*` 记录排障。

**#21 `0054bfa` / `6379bb98` 修复 CI 冒烟自检竞态**（1 文件，`.github/workflows/build.yml` 11 行改）：
- 根因：图标修好后暴露冒烟步骤 bug——工作流启动打包后的 exe 后**立刻** `Test-Path smoke-result.json`，而应用需 5–10s 才写出（日志显示 throw 在启动后 0.2s，之后应用检查项全部 PASS）。
- 改动：预建 `.shots` 目录 + 最长 4 分钟轮询 `smoke-result.json` 再校验。

## 五、环境坑与推送工作流（务必先看）

1. **TLS 拦截代理**：本机 `curl` 走系统证书链可通 `api.github.com`，Python 自带 OpenSSL 证书链 `SSL EOF`。推送必须走 `scripts/push-api.py`（已改为 curl 实现：`--retry 5` + 临时文件传体）。用法：`python scripts/push-api.py [commit]`，以远端 HEAD 为基底推送单次提交 diff，绕开非快进分叉。
2. **历史分叉**：常因 `core.autocrlf`（本仓库开启）——本地提交存 CRLF、API 推送存 LF → 树不同。对齐：`git -c http.sslBackend=schannel fetch origin main && git reset --hard origin/main`。
3. **`desktop/build/icon.ico` 已入库**：`.gitignore` 已加反白名单，**勿删**，否则 CI NSIS 再次失败。
4. **GitHub Actions 查 CI**：`GET /repos/byazlle/human-design-tool/actions/runs`；job 日志 302 → `curl -L` 可直接跟随（带 token 即可）。
