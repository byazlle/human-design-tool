### 4.2 本机网络/工具的三个坑（务必记住）

1. **TLS 只走 Node，不走 schannel。**
   `curl.exe` 对 `api.github.com` / `github.com` 全部返回 **HTTP 000**，stderr：`curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)`；PowerShell `Invoke-RestMethod` 报「基础连接已经关闭」。
   **唯一可用通道是 `node` 内置 fetch**（走 Node 自带 OpenSSL），已验证 `api.github.com` HTTP 200。git 网络操作**必须**加 `-c http.sslBackend=openssl`。

2. **`git` 不在 PATH。**
   可用二进制：`D:\AIws\WorkBuddy\resources\vendor\PortableGit\cmd\git.exe`（2.55.0.windows.3）。Python 调裸 `git` 会 `[WinError 2] 系统找不到指定的文件。`

3. **受限沙箱会打断 push。**
   报 `sh.exe: *** fatal error - NtCreateDirectoryObject(...msys-2.0S5-...): 0xC0000022` → `failed to execute prompt script (exit code 66)` → `fatal: could not read Username for 'https://github.com'`。
   **这是沙箱 + 凭据助手问题，不是网络/TLS 问题**，两条对策：宽权限运行，或 `-c credential.helper=` 禁掉助手。

### 4.3 两个既有脚本在本机当前不可直接运行

- `scripts/push-api.py`：双重阻塞——内部 `git()` 调裸 `git`（不在 PATH）+ 所有 HTTP 走 `curl` 子进程（TLS 000）。
- `scripts/publish-release.py`：同样走 `curl` 子进程 + `.env` token，同样受阻。

它们**在 CI 与其它环境仍可用**（登录 GitHub 的 runner 上 curl 正常），只是在本机需要先把 PortableGit 加进 PATH、并把 `curl` 换掉（或改用 `git` 直推）。逻辑本身值得保留：`sync_tree()` 以远端 main 为基底按 blob sha 全量比对（stale/missing/extra）再建树建 commit 快进 ref；`head_blob()` 用 `git cat-file blob HEAD:{path}` 取**原始字节**（注释写明：不能用工作区，commit 时 git 会做行尾归一化，否则 blob sha 永久不一致）；发布侧 `422 already_exists` 视为成功（CI 抢先上传），`abs(remote_size - local_size) <= 4096` 视为通过（PE 时间戳差异）。
