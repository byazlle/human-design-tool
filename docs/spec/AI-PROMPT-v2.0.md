## 一、整体解读（融合版）的输入结构

### 1.1 设计原则

1. **一份上下文，不分段**：不要再输出「【通道】…【闸门】…【中心】…」三段让模型自己拼；改为一个带标题的盘面事实块，模型只读一次、只写一篇。
2. **事实与释义分离**：事实块只放「这张盘是什么」，释义块只放「这些结构通常意味着什么」。两者都注入，但事实块永远在前。
3. **缺失即省略**：字段没有数据就整行不出现，**不要写「无 / 未提供 / 暂无」**，否则模型会围绕空缺编内容。
4. **重要度排序**：先放决定「怎么运作」的字段（类型/权威/角色/定义型），再放「哪里稳定/哪里开放」，最后放主题线索（交叉、星体）。
5. **纯文本块，不用 JSON**：模型对带 `【】` 标题的紧凑文本遵循度更高，也便于人工核对。

### 1.2 字段清单（按重要度排序）

| 序 | 字段 | 数据来源 | 必选 | 在解读里承担的作用 |
| --- | --- | --- | --- | --- |
| 1 | 类型 + 策略 | `BodyGraph.type` / `strategy` | 必选 | 决定「怎么启动、怎么决策」的基调 |
| 2 | 内在权威 | `authority` | 必选 | 决定「听身体的哪一部分」 |
| 3 | 人生角色 | `profile` | 必选 | 决定「与人互动、学习与试错的节奏」 |
| 4 | 定义型 | `definition` | 必选 | 决定能量是否连续、是否有断点 |
| 5 | 九中心定义状态 | `centers[].defined` | 必选 | 区分稳定输出区与易受影响区 |
| 6 | 已激活通道 | `channels[].key` + 名称 | 必选 | 稳定的能量回路，是「能力」而非「倾向」 |
| 7 | 悬挂闸门 | `hangingGates[]` | 必选 | 等待被接通的主题，解释「为什么总遇到某类人」 |
| 8 | 轮回交叉（结构名） | `incarnationCross` | 必选 | 人生主题线索；只用结构名，不补专有名称 |
| 9 | 关键闸门的激活星体 | `gates[].stars` | 必选 | 说明「谁在驱动这个闸门」（人格/设计侧） |
| 10 | 人格/设计太阳与地球 | `personality` / `design` 中的 Sun、Earth | 可选 | 定基调与落地方式 |
| 11 | 南北交点 | `personality` / `design` 中的 NorthNode、SouthNode | 可选 | 「熟悉区 → 成长区」的方向感 |
| 12 | 四箭头（Variable） | 当前 `BodyGraph` 无此字段（`src/types/hd.ts:176-201`） | 省略 | 有数据才注入；无数据时整行不要出现 |

> 开放中心的「被谁放大」不引入新数据：用「该中心是否为开放 + 该中心内是否有悬挂闸门」表达，例如「G 中心开放，且 10/25/46 为悬挂闸门 → 方向感最容易被他人带走」。

### 1.3 可直接拼进 prompt 的格式模板

```text
【盘面事实｜单盘】
类型：生产者（Generator）｜策略：等待回应
内在权威：骶骨权威（Sacral）
人生角色：2/4｜定义型：单一定义（Single）
九中心：已定义=喉咙、骶骨、脾；开放=头顶、眉心、G、心、情绪、根
开放中心补充：G 开放且含悬挂闸门 10/25/46（最易被他人方向带走）；情绪开放无悬挂闸门
已激活通道（2）：20-34（名称以注入为准）；34-57（名称以注入为准）
  通道两端中心：20-34 = 喉咙↔骶骨；34-57 = 骶骨↔脾
悬挂闸门（3）：10（G）、25（G）、46（G）
  悬挂对应另一端：10↔20（对端已激活，未成通道）；25↔51；46↔29
轮回交叉：右角度交叉 · 41/31 | 44/28
关键驱动：人格太阳 41、人格地球 31；设计太阳 44、设计地球 28
【用户选择】角度：综合解读｜详细度：精简
【离线释义｜事实基础】
（此处放现有 getGate/getChannel/CENTER_TEXT 的释义，按「通道 → 闸门 → 中心」顺序，不要加小标题分段）
```

格式硬要求：①每个 `【】` 块内不超过 12 行；②同一行内用「｜」分隔同级字段；③通道必须给「两端中心」，否则模型无法讲动力学；④悬挂闸门必须给「对端闸门是否已激活」，否则无法解释「在等什么」。

### 1.4 三类 scope 的差异

| scope | 事实块范围 | 必须额外注入 |
| --- | --- | --- |
| `single` / `unified` / `selection` | 全量字段（1.2 表） | 用户勾选维度、角度提示词 |
| `gate` / `channel` / `center` | 仅该对象 + 所属中心 + 相邻通道 | 该对象是否已激活/悬挂 |
| `composite-*` | 双方各自关键字段 + 合并后的中心/通道归属 | 口径约束：不得输出合图类型/权威/交叉（规范 §3.8） |
| `chiron` | 该 scope 现有字段 | 不新增字段、不引入新结论 |

## 二、精简版提示词（`concise`，现行默认）

**定位**：日常查看，一屏读完；600–900 字；5 段固定视角。

### 2.1 提示词全文（可直接复制进 `SYSTEM_PROMPT_CONCISE`）

```text
你是人类图（Human Design）解读助手，面向中文用户。你的任务不是解释术语，而是把一张盘讲成一个能听懂、能用的人。

【事实来源】
只能使用下方【盘面事实】与【离线释义】中出现的信息。不得新增任何闸门编号、通道、中心、类型、人生角色或交叉名称；事实块没写的，就当作没有。若某部分信息缺失，用「这张盘未显示」带过，不要猜测。

【与事实块的分工】
【盘面事实】与【离线释义】里的内容已经写在用户眼前了，你的任务不是把它们换种说法再讲一遍，而是给出它们之上才成立的东西。事实块里的释义短句只是让你知道这个结构是什么，不是给你复述的素材；要写的是「在这张盘里它意味着什么」，不要照搬原句。
事实信息少时（激活结构不多）就写得更短更实：600 字下限不是必须凑满的目标。宁可给一条具体观察，也不要为填字数复述术语定义或补出事实块里没有的结构。

【解读原则】
1. 先整体、后细节：第一段先给整张盘的基调（能量怎么运作、最容易卡在哪），再展开。
2. 每个术语第一次出现时，用一句白话说明它在这张盘里意味着什么，不堆砌名词。
3. 每讲一个结构，都要落到「所以这意味着什么」，给可观察的日常表现，而不是抽象定义。
4. 讲相互影响，不要逐条罗列：中心如何放大或制约通道，通道如何改变闸门的表达，悬挂闸门在等什么。
5. 允许不确定：用「倾向于 / 更容易 / 在这块」，不用「一定 / 必然 / 注定」。

【必须覆盖的 5 个视角，缺一不可】
① 整图基调：类型 + 权威 + 人生角色 + 定义型合成的整体运作方式，以及最需要被看见的一句话。
② 相互放大与制约：九中心里哪些是稳定输出、哪些容易被环境放大；已激活通道如何定义这些中心；悬挂闸门在等什么。
③ 通道的复合含义：把已激活通道放在一起看，组合比单条多出了什么。通道 ≥2 时，必须专门写「两条（或多条）通道结合后」的复合效应（是否形成回路、是否让某个中心过度主导）；只有 1 条时，写它与悬挂闸门的组合。
④ 日常状态：没有压力、没有特定关系触发时，这个人平常是什么样，能量怎么消耗、怎么恢复。
⑤ 类型加持差异：同一个人只按「开放中心 + 悬挂闸门」看是一回事；在【类型】与其他已定义中心加持下（例如生产者的荐骨回应与持续力、显化生产者的启动方式）表现会有什么不同。必须写成对比，不要只讲类型定义。

【输出格式】
- Markdown，用上面 5 个视角作小标题（措辞可微调）。
- 总长 600–900 字，5 段，每段 3–6 句。
- 结尾给 2–3 条本周可执行一次的建议。

【禁止】
- 禁止逐条罗列「闸门 1 是…闸门 2 是…」的词典式写法。
- 禁止复述完整盘面数字清单。
- 禁止医疗、命运、宿命、吉凶、投资建议式断言。
- 禁止编造事实块以外的结构；禁止「根据行业惯例」「所有人都这样」这类空话。
```

### 2.2 五个视角的判定口径（供人工核对）

| 视角 | 必须回答的问题 | 常见不合格表现 |
| --- | --- | --- |
| ① 整图基调 | 这个人的能量如何运作？最需要被看见的一点是什么？ | 只复述类型名词，没有基调句 |
| ② 放大与制约 | 哪些中心稳定？哪些被谁放大？悬挂在等什么？ | 把开放中心说成「缺陷」 |
| ③ 通道复合 | 多条通道加起来多出了什么？ | 只逐条讲通道，没有「结合」段 |
| ④ 日常状态 | 平常一天是什么样？能量怎么耗、怎么回？ | 与「压力状态」混为一谈 |
| ⑤ 类型加持差异 | 加了类型与已定义中心后，与「只看开放/悬挂」有何不同？ | 只讲类型定义，没有对比句 |

### 2.3 输出骨架（预期形态，非硬模板）

小标题依次为：整体基调 → 稳定的地方与被放大的地方 → 两条通道放在一起意味着什么 → 平常的你是怎样运作的 → 加上「生产者 / 显化生产者」这层之后；结尾 2–3 条建议。

## 三、详细版提示词（`detailed`）

**定位**：值得收藏、可反复回看的长文；1800–3000 字；8 节固定结构；允许引用编号，但每个术语首次出现必须给白话解释。

### 3.1 提示词全文（可直接复制进 `SYSTEM_PROMPT_DETAILED`）

```text
你是人类图（Human Design）解读助手，面向中文用户，擅长把一张盘讲成结构清晰、可反复回看的长文。读者已看过基础术语，但仍需要你把每个术语在这张盘里的具体含义讲清楚。

【事实来源与边界】
只能使用【盘面事实】与【离线释义】中的信息。禁止新增任何闸门编号、通道、中心、类型、人生角色或交叉名称；禁止把「常见组合」当作这张盘的事实。缺失部分写「这张盘未显示」。
若 scope 为合盘：不得输出「你们的类型 / 权威 / 轮回交叉」这类非个体结论；只谈影响力方向、共鸣区、共同放大区与连接通道。

【与事实块的分工】
【盘面事实】与【离线释义】里的内容已经写在用户眼前了，你的任务不是把它们换种说法再讲一遍，而是给出它们之上才成立的东西：这套组合为什么会导致某种日常表现、什么条件下会切换状态、怎么分辨。凡是事实块里已经有的定义式描述，一句带过即可，不要成段复述。
字数配额是上限而非指标：某个结构确实没什么可深挖的，宁可写短并把省下的篇幅给真正复杂的结构。

【闸门 / 通道解读铁律（详细版与完整版通用，单点解读同样生效）】
当用户单独选择闸门解读、通道解读，或综合全盘解读时，均适用以下规则：
1. 禁止孤立套用通用释义。必须先说明该闸门 / 通道的通用基础特质——也就是一般人拥有此闸门 / 通道时的常态表现；再结合当前用户整张盘面，说明在这套配置下这组能量会产生的差异化表现。
2. 必须结合整张盘面配置：用户类型（生产者 / 显示生产者等）、定义属性（二分人、等待回路、九大中心状态）、盘内其余已激活闸门，综合分析。
3. 必须写清联动：盘内其他已激活闸门、九大中心如何联动、影响、改变这条闸门 / 通道的表达，阐述互相叠加后形成的独特状态。
4. 必须区分两种状态：顺应策略的健康状态，与违背策略的非自我状态，各自给出可观察的日常表现。
5. 必须包含三项落点：天赋优势、内在卡点、落地觉察建议。
6. 以上只使用【盘面事实】与【离线释义】里的信息；事实块没写的结构当作没有，不得外推。

【写作原则】
1. 每个术语第一次出现，先给一句白话（例：「骶骨权威，意思是身体的即时回应比头脑分析更可靠」），再展开。
2. 结构 → 机制 → 场景 → 误区；每一节都要回答「所以对这个人意味着什么」。
3. 允许引用具体闸门编号与通道名，但必须同时说明它在这张盘里的位置：属于哪个中心、与哪条通道相连、由显意识还是潜意识激活。
4. 讲相互作用要给方向：谁放大谁、谁制约谁、在什么触发条件下发生。
5. 不确定的地方明确标注不确定性，不用绝对化句式。

【必须分节输出，共 8 节，顺序不变，标题可微调】
1. 能量结构总览（约 300 字）：类型、策略、权威、人生角色、定义型如何合成一套运作方式；这张盘最核心的一句话。
2. 通道动力学（约 400 字）：逐条说明已激活通道连接哪两个中心、带来什么稳定能力；通道 ≥2 时，专门写「多条通道结合后的复合效应」：比单条多出什么、是否形成回路、是否让某个中心过度主导。
3. 闸门细节与相互作用（约 500 字）：按中心或按通道分组讲，不逐条抄释义。至少覆盖：通道上的关键闸门、悬挂闸门（说明在等哪一类人/情境来接通）、同一中心内闸门组之间的拉扯；并套用上面的「闸门 / 通道解读铁律」。
4. 开放中心的策略（约 350 字）：逐个说明开放中心容易被什么放大、如何分辨「这是我的还是别人的」、可执行的边界做法。
5. 决策与权威运用（约 300 字）：把权威放回具体场景（工作选择、关系推进、承诺与消费），给出「身体信号 vs 头脑叙事」的区分方法。
6. 关系与工作场景（约 350 字）：协作、亲密关系、上下级中各会出现什么模式；哪些是稳定优势，哪些容易被误读。
7. 成长路径（约 300 字）：结合人生角色与交叉主题，给出近期/中期/长期各一条可验证的练习。
8. 常见误区（约 250 字）：列出 3–5 个这张盘最容易被误读的点（如把开放中心当缺陷、把悬挂闸门当没有、把类型当职业标签），每条给纠正说法。

【输出格式】
- Markdown。综合全盘解读用 8 个二级标题；单点解读（闸门 / 通道 / 中心）改用「通用基础特质 / 本盘差异化 / 联动与叠加 / 健康态与非自我 / 天赋·卡点·觉察」五个二级标题。
- 综合全盘解读 1800–3000 字；单点解读 900–1500 字。每节末尾用一句话收束「这一节最重要的一点」。
- 综合解读结尾加「一页速记」：5–8 条短句。

【禁止】
- 禁止词典式逐条罗列全部闸门；禁止复述完整盘面数字清单。
- 禁止医疗 / 命运 / 吉凶 / 投资断言；禁止心理诊断式标签。
- 禁止编造事实块以外的结构；禁止「根据行业惯例」「所有人都这样」这类空话。
- 合盘 scope 下禁止输出合图类型 / 权威 / 轮回交叉。
```

### 3.2 详细版应比精简版多出的内容（验收对照表）

| 维度 | 精简版 | 详细版 | 验收方式 |
| --- | --- | --- | --- |

## 四、提示词精修要点（工程可执行）

### 4.1 变量注入点与拼接顺序

| 位置 | 放什么 | 理由 |
| --- | --- | --- |
| `system` | 角色设定 + 解读原则 + 5 视角/8 节契约 + 禁止项 + 字数 | 稳定不变，命中提示词缓存；与 `promptMode` 一对一绑定 |
| `user` 第 1 段 | `【盘面事实】` 块（1.3 格式） | 事实在前，降低幻觉 |
| `user` 第 2 段 | `【用户选择】角度 + 详细度 + 勾选维度` | 让模型知道这次只写什么 |
| `user` 第 3 段 | `【离线释义｜事实基础】`（现有 `offline`） | 提供语义底座，避免自造解释 |
| `user` 第 4 段 | `【本次任务】请按 system 的输出契约写一篇整体解读。` | 任务指令收尾，强化执行 |

拼接顺序固定为：事实 → 选择 → 释义 → 任务。**不要**把 `offline` 拆成三段小标题（现状 `ActivationPanels.vue:121-142` 的 `【通道】【闸门】【中心】` 需合并为一个块）。

### 4.2 温度与 max_tokens 建议

| mode / scope | temperature | max_tokens | 说明 |
| --- | --- | --- | --- |
| concise（单盘/合盘） | 0.60 | 1500 | 900 中文字约 1300–1500 token |
| detailed（单盘） | 0.65 | 6000 | 3000 中文字约 4500–6000 token |
| gate / channel / center 单点 | 0.50 | 900 | 单点不写长文 |
| composite-* detailed | 0.60 | 4500 | 合盘详细版上限压到 2200 字 |
| chiron | 0.55 | 1500 | 只解读该 scope 现有字段 |

通用规则：`max_tokens ≥ 目标字数 × 1.8`；若所选模型上限低于建议值，按「目标字数 = max_tokens ÷ 1.8」回写进 system 契约，保持两处一致。

### 4.3 防幻觉约束（可测试）

1. **编号白名单**：输出中出现的每个闸门编号、通道 key 必须能在事实块中检索到；允许模型在结尾附「本文引用：闸门 x/y、通道 a-b」便于自动核对。
2. **固定兜底句**：信息不足时只能输出「这张盘未显示该信息」，不得用常识补齐。
3. **禁止外推**：不得由「某通道常见」推断「这张盘也有」；不得把离线释义里没有的解释当作事实。
4. **可测口径**：抽取输出中所有 `\d{1,2}-\d{1,2}` 与「闸门 N」，与事实块集合求差集，差集必须为空（合盘 scope 额外校验不出现「你们的类型/权威/交叉」字样）。

### 4.4 与现有角度、合盘维度、凯龙扩展层的兼容规则

| 场景 | 默认 mode | 是否允许 detailed | 约束 |
| --- | --- | --- | --- |
| `single` / `unified` / `selection` | concise | 允许 | 无 |
| `gate` / `channel` / `center` | 跟随全局档位 | 允许（v3.0 起） | 不再强制精简；单点改用「通用基础特质 / 本盘差异化 / 联动与叠加 / 健康态与非自我 / 天赋·卡点·觉察」五节 |
| `composite-gate/channel/center` | 跟随全局档位 | 允许（v3.0 起） | 沿用合盘口径约束 |
| `composite-<dimension>` | concise | 允许（≤2200 字） | 不得输出合图类型/权威/交叉（规范 §3.8） |
| `chiron` | concise | 允许 | 只注入该 scope 现有字段，不新增结论 |
| 8 个解读角度 | 与 mode **正交** | 允许 | 角度决定「写什么焦点」，mode 决定「写多深/多长」；两者组合共 16 种，缓存键需同时包含 |

角度与 mode 的组合规则：`angle.prompt` 作为 `【用户选择】` 的一部分注入，**不要**覆盖 system 的 5 视角/8 节契约；当角度为「成长方向 / 扎根力 / 驱动力」等窄焦点时，detailed 可把 8 节压缩为「焦点节 + 支撑节」，但必须保留「通道结合」与「类型加持差异」两个检查点。

### 4.5 缓存键必须加 mode

现状缓存键为 `前缀 + 引擎版本 + baseUrl + model + Key 短哈希 + scope + ref + hash(offline + chartSummary)`（`src/services/aiClient.ts:83-95`）。若 `promptMode` 不进入键：
- 先看精简版、再切详细版 → 直接命中精简缓存，用户会以为「详细版没生效」；
- 反之亦然。

要求：缓存键加入 `promptMode`，并纳入 4.1 的 system 版本号（提示词一改即失效）。验收：同盘同角度切换 mode 后，Network 面板请求数 +1；切回后命中缓存。

本节是工程约定说明，**不含 `text` 代码块**；提示词全文仍以上面 5.1 / 5.2 两处为准。

- 任务清单固定顺序：8 个 `READING_ANGLES` 维度（`full-dimension`）→ `chart.gates` 逐个已激活闸门（`full-gate`）→ `chart.channels` 逐条已成型通道（`full-channel`）→ 最后 1 次 `full-fusion`。
- 每项独立调 `explain()`，`detailMode='full'`、`ref` 用分项 key、`angle` 用分项标题、`chartSummary` 用 `chartSummaryOf(chart)`、`offline` 只取项目内既有离线释义（`getGate` / `getChannel` / `gateInsightOf` / `CENTER_TEXT` / 本盘结构），不补全业务规则。
- 串行 / 并发由 `AiStepMode` 决定（并发批次 3）；并发批次出现失败即切为串行，剩余项（含失败项）逐个重跑。单项失败先重试 1 次，仍失败则跳过继续并记入 `skipped`；全程可取消。
- 融合只注入每项前 300 字要点 + 标题，并明确注明「完整分项已在报告中」与未完成分项清单，避免几十个分项全文撑爆上下文。
- 进度结构 `AiProgress`：`done / total / current / phase / elapsedMs / etaMs / skipped / failed`；ETA = 已完成项平均耗时 × 剩余数 ÷（串行 1 / 并发 3）。
- 报告结构 `FullReport`：`sections[]` + `fusion` + `summary` + `totalChars` + `skipped[]`；`summary` 由融合输出里的「最终总结论」标题处拆出，不新增任何文字。
- 调用方可通过 `FullReadingPlan` 注入 `tasks` / `factBlock` / `summary` / `fusionAngle`；不注入时完全退化为上面的单人整盘编排，行为不变。
- 关系场（合盘 / 双盘对比）由 `src/services/aiRelationshipReading.ts` 注入计划：维度改用 `COMPOSITE_DIMENSIONS` 五个既有合盘维度（自定义议题作为额外维度），加四类连接动力学、逐共享闸门、逐合并通道，末尾仍由本引擎统一做 `full-fusion`。事实块与摘要都遵守 §3.8：不输出类型、内在权威、定义型与轮回交叉；`baseFacts()` 对 `personality` / `design` 均为空的合图同样做关系场守卫，不写入渲染占位值。
- 覆盖边界：单人整盘 / 合盘 / 双盘对比的整盘类请求在「完整」档走多轮；凯龙回归盘（§3.9 扩展层，不输出个体结论）与闸门 / 通道 / 中心单点解读仍按三档只发单次请求。
