## 二、战略主线（Why）

过去一个月产品以**高速功能叠加**为主（约两周 6 个版本，重心全在 AI 解读深度）。下一步的瓶颈不是"还能加什么功能"，而是三件事：

1. **口径债务**：`docs/review/` 仍有大量未确认的计算 / 术语 / 范围冲突（R1–R38、C-01～C-28），其中结果级项可能改变盘面。**这些不是可推断项，必须先由项目所有者确认**——本套文档只登记门禁，不代替决策。
2. **价值不可见**：产品无遥测、无用户研究数据，无法回答"用户到底用不用、哪一步流失"。继续凭感觉堆功能风险越来越高。
3. **已知体验短板**：移动端 38px 命中区（< 44px）、真实 390px 设备未验证、长列表性能、离线态、加载骨架等 P2 项长期挂账。

因此下一阶段的战略主线定为：

> **从"功能叠加"转向"口径收口 + 价值可见 + 体验补齐"，再做有数据支撑的新能力投入。**

| **Later**（方向性） | 2027 Q2 起 | 新能力探索 | 行运推演、商业基准比对、交叉名称精修——需数据 / 授权样本到位才启动 |

版本号建议：Now 产出 **v3.7 / v3.8**，Next 产出 **v3.9 / v3.10**，Later 视范围定 v4.0。
**版本纪律**：产品版本（3.x）与提示词版本（PROMPT_VERSION，`4.0`）是两条独立线，不可混改；改提示词必跑 `node scripts/sync-prompt-spec.mjs`。

## 四、北极星与指标（摘要）

- **北极星候选**：`每周完成一次有效解读并保存/导出的活跃档案数`（口径待确认，见 ROADMAP 第 5 节）。
- **驱动指标**：解读采纳率、批量导入渗透率、解读闭环完成率。
- **健康指标**：CI 通过率、桌面冒烟 29/29、测试全绿数、口径门禁关闭率、P0 缺陷数。

## 五、使用前必读的三条约束

1. **口径不推断**：凡涉及业务规则 / 术语 / 流程状态 / 边界的未确认项（R1–R38、C-01～C-28），一律走 [ROADMAP 第 8 节确认门禁](ROADMAP.md#8-待确认门禁不推断清单)；确认前不得作为结论或改动依据。
2. **内核零改动是默认前提**：曼陀罗锚点、通道判定、合盘口径、SCHEMA_VERSION 在未经显式确认前不属于任何迭代范围。
3. **发布纪律**：版本号单一来源为根 `package.json`；推送通道会在 curl / Node fetch 间变化，发布前先探测；CI tag 工作流是唯一权威产物来源。
